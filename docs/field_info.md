| 항목 | 값 |
|---|---|
| 제품 | ELP IMX678 광각 4K 60FPS USB 3.0 카메라 |

| 렌즈·화각 | 5 mm, **94°** (2026-10-09 교수님 확인). 현재 버전에서 카메라 스펙 변경 없이 고정 |

### 설계에 미치는 영향 (검토 메모)
- **해상도**: AI Hub 학습 영상은 1440×1080(판당 계란 약 8~12개, 계란당 약 230×290 px). 4K 에서 같은 화각이면 계란당 픽셀이 약 2.7배 → 미세크랙에 유리. 다만 검출기 입력 640px 로 축소하면 이점이 사라지므로 **판 전체 검출은 축소본, 크랩 분류는 원본 해상도 크롭** 구조가 자연스럽다(현재 2단계 구조와 일치). 화각이 정해져야 판당 계란 수와 크롭 크기를 계산할 수 있다.
- **60 fps**: 계란이 이동·회전하는 동안 한 계란을 여러 프레임에 담을 수 있어 **다중 프레임 투표**가 가능. 라인 속도와 화각이 정해지면 계란 1개당 프레임 수를 계산.
- **USB 3.0 대역폭**: 4K60 은 비압축으로 USB 3.0 한계를 넘으므로 카메라가 MJPEG 압축 출력일 가능성이 높음. JPEG 압축은 미세크랙 선을 뭉갤 수 있어 **품질 설정 확인·가능하면 YUY2/저압축 모드 또는 fps 를 낮춰 비압축** 검토 필요.
- **노출·롤링셔터**: 이동 중 촬영이면 모션 블러. IMX678 은 롤링셔터이므로 노출 시간을 짧게(조명 강하게) 가야 함. 투광(백라이트) 광량 확인 필요.
- **드라이버**: UVC 라 OpenCV `cv2.VideoCapture` 로 바로 읽힘. 파이프라인의 캡처 단계에 그대로 연결 가능.

### 확인 요청 목록
- 화각(렌즈 초점거리) 또는 설치 높이와 촬영 범위(가로×세로 cm)
- 출력 포맷(MJPEG/YUY2)과 실제 사용 해상도·fps 설정
- 조명 종류(투광/반사광), 광원 파장·광량, 계란 이동 속도

## 3. KS B 7956-4 (축산 사양관리기기 — 데이터수집 기준 — 제4부: 닭) 중 파각란검출기 요구사항

출처: 교수님 게시(2026-10-08), 표준 문서 https://www.standard.go.kr/streamdocs/view/sd;streamdocsId=72059385502626382

| 조항 | 내용 |
|---|---|
| 4.3.1 일반사항 | 영상 또는 음향 분석 기술로 껍질이 깨지거나 금이 간 계란을 검출·분리 제거하는 장치. 컨베이어 벨트(1) + 파각란 검사 장치(2) |
| 4.3.2 송출 데이터 | 기기는 **통신 기능을 포함**해야 하며 기본 송출 데이터는 a) 검출기 번호(농장 단위 고유 정수 ID), b) 처리란 개수(개/일, 정수), c) 파각란 개수(개/일, 정수), d) 설정 시간(YYYYMMDDhhmmss) |
| 4.3.3 측정 기준 | **파각란 미검출 비율 7% 이내**. 비고: 미검출 비율 = **검출기를 거쳐 배출된(통과한) 정상란 중 파각란의 비율** |

### 3.1 측정 기준 해석 (중요)
KS 의 미검출 비율은 "파각란 중 놓친 비율(1 − Recall)"이 아니라 **"정상으로 통과한 계란 중 파각란이 섞인 비율"** 이다. 따라서 시험 배치의 파각란 비율(p), 모델의 파각 Recall(r), 정상 오검출률(f)에 따라 값이 달라진다.

미검출 비율 = p·(1−r) ÷ [ (1−p)·(1−f) + p·(1−r) ]

| 시험 배치의 파각란 비율 p | Recall 90%, 오검출 10% | Recall 93% | Recall 95% |
|---|---:|---:|---:|
| 5% (현장 통상) | 0.6% | 0.4% | 0.3% |
| 20% | 2.7% | 1.9% | 1.4% |
| 50% (결함 위주 시험) | 10.0% | 7.2% | 5.3% |

- 현장 통상 비율(수 %)에서는 기준을 쉽게 만족하지만, **시험 수량·구성 기준이 없어** 평가자가 파각란 위주 배치로 시험하면 Recall 93% 로도 아슬아슬하다.
- 따라서 내부 목표는 **최종 판정(3회 촬영 투표 후) Recall ≥ 95%** 로 잡는 것이 안전하다. 현재 AI Hub 단일 시점 모델이 Recall 95% 에서 정상 오검출 9.6% 이므로, 3회 투표로 오검출을 낮추면서 Recall 을 유지하는 설계가 목표.
- 시험 방법(배치 구성, 수량)을 기업·교수님과 미리 합의해 두는 것이 필요.

### 3.2 송출 데이터 → 모니터링 웹서비스 최소 요구
필수-4(웹서비스)의 최소 데이터 항목이 표준에 정해져 있다: 검출기 ID, 일별 처리란 수, 일별 파각란 수, 설정 시각. 현재 파이프라인의 판정 로그(JSONL: 판 시퀀스, 계란별 판정)에서 일 단위 집계로 바로 만들 수 있다. 전송은 WiFi 기본, LTE Cat.M1 옵션 → 저대역폭을 고려해 **집계값 위주 전송 + 이미지는 선택적(오판 사례만)** 으로 설계.

## 4. 시제품 사진·샘플 영상 관찰 (2026-10-09)

기업 개발 중 데이터에서 나온 내용이라 **공개 저장소에는 싣지 않는다.** 내부 기록은 `docs/private/field_observations.md` (git 미추적, 팀 내부 전달만). 설계에 반영된 결론만 적는다.

- 샘플 영상은 흰색란만 촬영한 것(교수님 확인). 대상은 **황색란(갈색)과 흰색란 모두** → 두 난각색 데이터가 모두 필요하고 노출 설정도 난각색별 확인 필요.
- 껍질의 잉크 날짜 도장이 선명 → 크랙과 혼동 가능, 학습 데이터에 반드시 포함.
- AI Hub 와 촬영 구조가 달라 **zero-shot 성능은 낮음**(실측: 전부 크랙 판정). AI Hub 가중치는 사전학습 초기값으로만 사용하고 자사 라벨로 미세조정.
- 계란 자리가 고정이라 **판 전체 검출기 대신 고정 ROI 크롭**으로 단순화 가능 → 추론 비용 감소.

### 4.1 데이터 파이프라인 변경 메모
1. 영상 → 프레임 추출(회전 3단계에 맞춰 샘플링) → 카메라 화면 분리 → 자리별 ROI 크롭 (`scripts/ingest_video.py`).
2. 라벨링: 크롭 단위로 정상/파각(+세부 유형 메모), 가능하면 도장 유무·백색/갈색 메타 기록. AI Hub 2클래스 모델 예측을 초기 라벨로 제시(반자동).
3. 기업에 요청: 카메라 원본 프레임(또는 무압축 저장), 회전 단계 신호(어느 프레임이 1/2/3회차인지), 조명 사양.

### 2.6 설계에 미치는 영향 (검토 메모)
1. **운영점 재설정**: KS 기준은 미검출 7% 미만 → Recall 93% 이상. 3회 촬영 투표를 쓰면 단일 시점 Recall 이 93% 보다 낮아도 최종 Recall 93% 달성 가능. 정상 오검출은 KS 에 명시 없음 → 기업과 허용치 협의 필요(현재 단일 시점 Recall 95% 에서 9.6%).
2. **장비 성능**: Orin Nano 는 RTX 4060 대비 대략 5~10배 느림. 현재 계란당 1.9 ms → Orin 에서 10~20 ms 예상. 사이클당 6개 × 3회 = 18 크롭이므로 TensorRT FP16 로 충분히 실시간 가능하나 **실측 필요**.
3. **데이터 파이프라인 신규**: 영상 → 프레임 추출 → 계란 검출(AI Hub 검출기 zero-shot) → 크롭 → 라벨링 도구 → 자사 데이터셋. 라벨링 효율을 위해 AI Hub 모델의 예측을 초기 라벨로 제시하는 반자동 라벨링 권장.
4. **검란 방향 전환**: 종란(유정/무정/부화중지) 분류는 11월 검란기 환경 구축 후. 선행연구상 **촬영 일령이 정확도를 지배**(1일차 47% → 5일차 98%) → 일령별 데이터 수집 계획이 핵심. AI Hub 식용란 검란 결과는 참고용.
5. **웹 모니터링 서비스**: 판정 결과·이미지·장비 상태를 WiFi/LTE Cat.M1 로 서버에 올려 보는 구조. 현재 파이프라인의 JSONL 판정 로그와 알람 코드를 그대로 전송 데이터로 쓸 수 있음. 설계 문서 별도 작성 필요.
6. **카메라 2대·회전 3회**: 같은 계란의 3프레임을 묶는 트래킹/동기화 로직이 필요 (장비가 회전 타이밍을 알려주면 단순해짐 → 기업에 확인).
