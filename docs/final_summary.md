> 모든 수치는 AI Hub 계란 데이터(다운로드본 = 공식의 90%) 내부 test 분할(촬영일×지역 group split) 기준이며, 클래스명은 `configs/class_codes.yaml` 가설(혈반육반·거품·먹통은 육안 확인)이다. 장비: RTX 4060 Laptop 8GB. 원본 수치: `experiments/RESULTS.md`, 단계별 문서: `docs/phase*.md`.

## 1. 결론 한 줄

**2단계 구조(YOLO11n 계란 검출 → 크롭 분류)를 채택하고, 배출 판정은 "크랙 vs 정상" 전용 2클래스 헤드로, 소분류 보고와 검란은 33클래스 통합 모델로 운용한다.** 파각 Recall 95% 운영점에서 정상란 오검출 9.6%(Recall 90%: 2.9%), 검란(혈반·육반)은 Recall 88%에서 정상 오검출 0.4%.

## 3-1. 3클래스 모델과 배출 정책 시뮬레이션 (2026-09-25 추가, `docs/reject_policy.md`)

정상/크랙/기타결함 3클래스(320px)를 학습해 "정상만 통과" 정책을 시뮬레이션했다. 배출 점수 = 1 − p(정상).

| 정책 | 3클래스 | 33클래스 | 6클래스 |
|---|---:|---:|---:|
| 크랙 95% 배출 시 정상 오배출 (크랙만 기준) | 12.3% | 14.3% | 17.7% |
| 모든 결함 95% 배출 시 정상 오배출 | 33.3% | 31.2% | 29.2% |
| 모든 결함 90% 배출 시 정상 오배출 | 18.4% | 16.5% | 15.3% |

- 크랙만 놓치지 않는 기준이면 2클래스 전용 모델(9.6%)이 여전히 최선이다.
- **"모든 결함 배출" 정책은 비싸다**: 탈색·이물질 일부가 투광 영상에서 정상과 구분되지 않아, 결함 95% 를 잡으려면 정상의 약 30% 를 버려야 한다. 이는 모델 문제라기보다 **어떤 결함을 배출 대상으로 볼지의 정책 문제**다(예: 탈색은 통과, 크랙·혈반·이물질만 배출). 사용자 결정 필요.
- 배포 지연: 크롭 전처리·전송을 GPU 로 옮겨 판당 분류 66 → 13 ms, 판 합계 23 ms, 계란당 p50 1.9 ms (`docs/phase7_deployment.md`). 남은 병목은 검출 전·후처리(10 ms).

## 3-3. 도메인 이동 예고편 — 로보플로우 공개 사진 sanity check (2026-09-26, `docs/roboflow_sanity.md`)

투광 2클래스 크랙 모델을 촬영 환경이 전혀 다른 공개 사진(스톡 사진, 그레이스케일 변환)에 그대로 적용: cracked-eggs(크랙 1,161 / 정상 989)에서 **AUROC 0.901**, egg-crack-detection(크랙 1,515)에서 Recall 1.000. 크랙 특징 자체는 전이되지만, AI Hub 임계값을 그대로 쓰면 정상 오검출 76% → **새 환경에서는 임계값 재조정(또는 소량 미세조정)이 반드시 필요**하다. 자사 라인은 이보다 훨씬 가까운 도메인이므로 zero-shot 이 이 수치보다 좋을 것으로 예상.

## 4. 한계와 주의

1. **코드표 미확정**: 크랙 소분류 이름(2/1~2/7)은 나열 순서 가정, 정상·탈색·이물질·기형 소분류 이름 미상. 공식 코드표로 확정 필요.
2. **2클래스 모델의 음성은 정상만**: 라인에서는 탈색·이물질 크롭도 들어오므로 3클래스(정상/크랙/기타) 재학습으로 확인 필요.
3. **COLOR 세척별 비교 불성립**: 세척 코드가 촬영 세션·클래스 분포와 완전히 얽힘. MONO 는 세척이 단일값. → 자사 데이터에서 같은 세션에 세척/비세척 혼합 촬영.
4. **COLOR test 는 촬영일 1개**: 크랙 110개뿐이라 COLOR 수치의 신뢰구간이 넓다.
5. **도메인 이동 미검증**: AI Hub 선별기와 자사 라인의 조명·카메라 차이. Phase 6 은 데이터 입고 후.
6. 실험 재현성: git 저장소 미초기화라 실험 기록의 git hash 가 `no-git`(SUMMARY 에 재현 불가 표시). 초기화 권장.

## 4-1. 미검출 크롭 육안 검토 (2026-09-25, `검수/06_미검출_파형크랙/`)

파형크랙(2/7) 미검출 크롭 40장을 검출 크롭 40장과 나란히 보면, **미검출 쪽은 320px 크롭에서 균열이 사실상 보이지 않는다**(검출 쪽은 가는 밝은 균열선이 다수 보임). 즉 이 미검출은 모델 한계보다 **단일 시점 촬영의 한계**(균열이 반대편에 있거나 이 해상도에서 안 보임)일 가능성이 크다. 선행연구(YOLOv5+ByteTrack, 5프레임 연속 판정)가 시사하듯 **계란 회전 중 다중 프레임 촬영·투표**가 현장에서 가장 큰 개선 수단이 될 것이다. 사용자 육안 확인 요청 중.

## 5. 다음 단계 제안 (우선순위)

1. **배출 정책 확정**(어떤 결함을 배출하는가) → 그 정책 기준으로 운영점·오배출률 최종 보고 (`scripts/reject_policy.py` 재실행이면 됨)
2. **다중 프레임/다면 촬영 검토**: 미검출 파형크랙은 단일 시점에서 균열이 안 보이는 경우가 대부분 → 현장 카메라 구성에서 가장 큰 개선 여지
3. 자사 라인 데이터 100~300장 zero-shot → 학습 곡선 (phase6 스크립트), 세척/비세척 혼합 촬영
4. 지연: 리사이즈까지 GPU 처리, 검출 전·후처리 정리, TensorRT (장비 확정 후)
5. 선택: YOLO26n 검출기 비교, 384px 크롭, 2/7 라벨 정제 후 재학습
